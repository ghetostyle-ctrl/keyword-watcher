# 키워드와처

시장과 경쟁사의 **월간 검색량 변화**를 매일 기록하는 개인용 키워드 트렌드 대시보드입니다. TrendScout의 기능 구성을 참고해 독립적으로 구현했습니다.

처음 설치한다면 [순서대로 요청하는 설치 가이드](START_HERE.md)의 1~7단계 요청문을 AI에게 보내세요. 간단한 실행 방법은 [공유·설치 안내](SHARE_GUIDE.md)에 있습니다. 각 사용자가 본인 API 키와 별도 DB를 사용합니다.

## 바로 실행

이 PC에서는 `http://127.0.0.1:3000`으로 접속합니다. Windows 자동 실행을 설치한 경우 로그인 시 숨김 서버가 시작됩니다. 수동 실행이 필요한 환경에서는 `Start-KeywordWatcher.cmd`를 더블클릭하세요. 수동 실행 창을 닫으면 해당 서버가 종료됩니다.

직접 실행하려면 [Bun](https://bun.sh/) 1.3.14 이상을 설치하고 프로젝트 폴더에서:

```sh
bun install --frozen-lockfile
bun run build
bun run start
```

개발 모드: `bun run dev` 후 `http://127.0.0.1:5173`. 운영 모드는 빌드된 화면과 API를 같은 3000번 포트에서 제공합니다.

## 포함된 기능

- 카테고리 및 7·14·30일 비교 필터, 마지막 수집 날짜
- 증감률 1위와 신규 관측 키워드를 요약하는 시장 시그널
- 검색량 **증가량** 기준 TOP 3, 일시정지 가능한 티커
- 신규 키워드 날짜별 목록, 검색·정렬·상세 기록 조회
- 8개 카테고리별 시작 키워드 30개 선택·일괄 등록, 직접 카테고리 입력, 카테고리 필터
- 키워드 등록, 수집 일시 중지/재개, 카테고리 관리
- 실제 CSV 가져오기와 내보내기
- 네이버 검색광고 수집, KST 일일 스케줄러, 실행 기록
- 휴대폰·태블릿·데스크톱 반응형 화면

처음 실행하는 DB에는 예시 검색량이나 가짜 순위가 없습니다. 실제 API 키를 넣거나 보유한 CSV를 가져오기 전까지 빈 상태가 정상입니다. AI/LLM 요금 없이 저장 데이터의 계산 결과로 시그널 문장을 만듭니다.

## 실제 데이터를 연결하는 방법

이 앱은 임의 검색량이나 예시 스냅샷을 생성하지 않습니다. 새 데이터베이스는 비어 있습니다. 기존 실측 CSV를 가져오거나 네이버 검색광고 API를 연결한 뒤 키워드를 등록하세요.

### 네이버 검색광고 API

프로젝트 폴더에서 `.env.example`을 `.env`로 복사하고 검색광고 계정의 API 사용 관리에서 확인한 아래 값을 입력합니다.

- `NAVER_SEARCHAD_API_KEY`: API 키
- `NAVER_SEARCHAD_SECRET_KEY`: 시크릿 키
- `NAVER_SEARCHAD_CUSTOMER_ID`: 고객 ID

DataLab Search Trend/Shopping Insight 키는 이 수집기에 사용할 수 없습니다. 해당 API는 상대 지수를 제공하며, 이 앱은 검색광고 `/keywordstool`의 PC·모바일 월간 검색량 합계를 저장합니다. API 키는 서버 환경 변수에만 보관되며 화면과 상태 응답에는 설정 여부만 노출됩니다.

`bun run dev`로 개발 실행하거나 `bun run build` 후 `bun run start`로 같은 서버에서 화면과 API를 제공합니다. 기본 주소는 `http://127.0.0.1:3000`이며 개발 화면은 Vite 주소를 사용합니다.

추적 키워드 화면의 **카테고리로 시작하기**에서 관심 분야를 고르고 필요한 키워드를 선택한 뒤 **추적하기**를 누르세요. 각 카테고리는 직접 준비한 시작 키워드 30개이며 네이버 인기 순위나 검색량 데이터가 아닙니다. 기존 키워드는 중복 등록하거나 수집 상태를 바꾸지 않습니다. 브랜드명은 개별 등록할 수 있고 카테고리도 직접 입력할 수 있습니다. 등록 후 `지금 수집`을 누르세요. 최대 100개까지 등록할 수 있습니다. 키워드 이름의 공백·대소문자 차이는 동일 키워드로 취급합니다. 관련 키워드가 응답되어도 정확히 일치하는 키워드만 채택합니다.

### 매일 수집

`.env`에서 `SCHEDULER_ENABLED=true`, `COLLECTION_HOUR=9`로 설정하고 서버를 계속 실행하면 한국 시간 오전 9시에 수집합니다. 지정 시간 이후 서버가 시작되면 당일 미수집분을 시도합니다. 실패한 자동 수집은 30분 간격으로 재시도합니다. 컴퓨터 절전·종료 중에는 실행되지 않습니다.

서버 내부 스케줄러 대신 OS 스케줄러에서 프로젝트 폴더를 작업 디렉터리로 지정하고 `bun run collect`를 매일 실행해도 됩니다. Windows 작업 스케줄러에서는 프로그램에 `bun.exe`의 절대 경로, 인수에 `run collect`, 시작 위치에 프로젝트 폴더를 입력합니다. 두 방식 모두 SQLite에 저장된 일별 성공 기록과 프로세스 간 잠금을 공유합니다.

### Windows 자동 실행 설치

이미 `.env`와 빌드가 준비된 프로젝트 폴더에서 아래 명령을 실행합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./scripts/windows/Install-Tasks.ps1 -StartNow
```

`KeywordWatcher-Server`는 현재 Windows 사용자 로그인 시 서버를 숨김 실행하고, `KeywordWatcher-DailyCollection`은 매일 오전 9시에 수집합니다. 이 PC의 한국 시간대를 사용합니다. 서버가 종료되면 작업 스케줄러가 재실행을 시도합니다. 로그인된 사용자와 깨어 있는 PC가 필요하며, 잠금 화면에서는 실행됩니다. PC 전원·절전 설정은 바꾸지 않습니다.

상태 확인: `scripts/windows/Get-Status.ps1`. 자동 실행 해제: `scripts/windows/Remove-Tasks.ps1`. 해제는 이 프로젝트가 등록한 두 작업만 제거하며, 기본적으로 현재 실행 중인 프로세스는 유지합니다. 로그는 `data/logs/`에 고정 이벤트와 종료 코드만 기록하고 API 키를 기록하지 않습니다.

설치 시 기본 주소 `127.0.0.1:3000`을 사용하세요. 다른 앱이 3000번 포트를 쓰면 중복 서버를 시작하지 않습니다.

하루에 성공한 수집은 다시 쓰지 않고 기존 성공 결과를 반환합니다. 성공 후 추가한 키워드는 다음 날 수집부터 포함됩니다. CSV 가져오기는 같은 키워드·날짜의 값을 명시적으로 갱신할 수 있습니다.

### 저장과 계산

- 데이터베이스: `data/trendwatch.sqlite`. `DATABASE_PATH`로 변경할 수 있습니다.
- `keyword_snapshot`: 키워드, 카테고리, 월간 검색량, 수집일과 원본 표시값·범위·출처.
- `tracked_keyword`: 수집 대상과 활성 여부. 수집을 일시 중지해도 과거 기록은 남습니다.
- `collection_run`: 시작/종료 시간, 요청·응답 수, 성공/실패 상태.
- `raw_response`: 성공적으로 받은 검색광고 응답 원문. API 자격 증명과 요청 헤더는 저장하지 않습니다.

수집일은 한국 날짜를 기준으로 합니다. 기준 날짜는 오늘이 아니라 **가장 최근 저장된 수집일**이며, 7·14·30일 전의 정확한 날짜와 비교합니다. 그 날짜가 없으면 근처 날짜로 대체하지 않습니다. 일곱 날짜가 있다는 이유만으로 비교하지 않으며, 예를 들어 9월 21일의 7일 비교에는 9월 14일 값이 필요합니다.

월간 검색량은 해당 시점에서 API가 제공하는 월간 값입니다. 두 스냅샷의 차이는 월간 검색량 추정치 변화이며, 해당 일의 검색 횟수나 지난 7일의 검색 횟수 합계가 아닙니다. `첫 등장`은 이 데이터베이스에서 처음 관측된 날이며 시장에서 처음 생성된 키워드를 의미하지 않습니다.

`<10`은 0으로 변환하지 않습니다. 각 하위 값의 범위를 0~9로 보존하여 합계를 범위로 표시합니다. 현재 또는 기준 값이 범위이면 증감량·증감률을 계산하지 않습니다. 기준 값이 정확히 0이면 증감량만 계산하고 증감률은 표시하지 않습니다. TOP 3은 계산 가능한 **양수 증감량**으로 정렬합니다.

한 키워드라도 실패하면 해당 실행의 모든 스냅샷을 저장하지 않습니다. 부분 응답 수와 오류를 로그에 기록하고, 받은 원문은 진단용으로 보존합니다. 덕분에 일부 키워드만 있는 불완전한 날짜를 완전한 수집 결과처럼 표시하지 않습니다.

### CSV

UTF-8 CSV의 필수 헤더는 아래와 같습니다. 빈 템플릿에는 데이터 행을 넣지 않습니다.

```csv
keyword,category,monthly_volume,snapshot_date
```

`monthly_volume`에는 0 이상의 정수 또는 `<10`, `snapshot_date`에는 `YYYY-MM-DD`를 사용하세요. 빈 검색량·잘못된 날짜·미래 날짜는 거부됩니다. 파일 한도는 UTF-8 기준 2MB, 10,000행입니다. 따옴표로 감싼 쉼표·줄바꿈과 BOM·CRLF를 지원합니다.

내보내기에는 `volume_min`, `volume_max`도 포함됩니다. 범위 검색량을 다시 가져올 때는 `monthly_volume`을 비우고 두 범위를 제공할 수 있습니다. 공식처럼 해석될 수 있는 문자열에는 내보낼 때 아포스트로피를 붙이고 다시 가져올 때 복원합니다. 단순 엑셀 저장 방식에 따라 숫자나 키워드 표기가 변할 수 있으므로 원본 UTF-8 CSV를 보관하세요.

CSV 가져오기는 전체 파일을 검증한 뒤 하나의 트랜잭션으로 저장하고 수집 대상 키워드도 등록합니다. 같은 키워드·날짜는 중복 행을 만들지 않고 갱신합니다. 가져오기 실패 시 파일의 어떤 행도 반영하지 않습니다.

### 실행 범위와 검증

이 버전은 개인 PC에서 실행하는 로컬 앱입니다. 외부 네트워크 주소 바인딩을 거부하고 API 쓰기 요청을 로컬 화면으로 제한합니다. 공개 배포 전에는 로그인, 사용자별 데이터 분리, HTTPS, 운영용 스케줄러·백업 구성이 필요합니다.

2026-09-21 이 PC에서 실제 검색광고 인증정보를 연결하고 API 응답을 확인했습니다. 연결 확인 조회는 DB에 저장하지 않았으며, 추적 키워드 범위가 정해지기 전까지 운영 DB는 비어 있습니다. 격리된 메모리/임시 데이터베이스에서 계산·CSV·HTTP·HMAC·수집 잠금 테스트를 수행하며, 테스트 데이터는 기본 데이터베이스에 넣지 않습니다.

## 구조와 검증

- `src/`: React 화면, 공통 컴포넌트, CSS 디자인 토큰
- `server/`: Hono API, SQLite 저장, SearchAd 수집 및 스케줄러
- `shared/contracts.ts`: 서버·화면 간 데이터 계약
- `tests/`: 격리된 DB와 로컬 서버를 사용하는 자동 테스트
- `DESIGN.md`: 화면 설계와 접근성 기준

```sh
bun test ./tests
bunx tsc --noEmit
bun run check
bun run build
```

검증 현황과 한계는 `QA_REPORT.md`를 참고하세요. 실제 인증·응답은 확인했으며, 등록 키워드의 일일 저장과 7일 비교 운영 검증은 데이터가 쌓인 뒤 진행합니다.
